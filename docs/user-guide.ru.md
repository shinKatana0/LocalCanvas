# Руководство пользователя LocalCanvas

[English](user-guide.md) · **Русский** · [日本語](user-guide.ja.md)

Всё, что нужно, от пустой папки до картинки на телефоне. Если ещё не читали,
начните с [README.ru.md](../README.ru.md): там сказано, что такое LocalCanvas и
чем он намеренно не является. Канонический текст этого руководства — английский:
[user-guide.md](user-guide.md).

`LocalCanvas.exe`, трей-лончер для Windows, — обычный способ запускать
LocalCanvas начиная с v0.2.0. Разделы 1–6 идут этим путём. Всё, что он делает, —
вызов тех же скриптов, которыми пользуется командная строка, — ничто из того,
что было верно для командной строки, не перестало быть верным, оно просто уже
не первое, что вам показывают. Раздел 14 — это она, командная строка, разобрана
целиком: для неполадок, для запуска без человека и для компьютеров, на которых
лончер не запускается (см. [Известные ограничения](#16-известные-ограничения)).

Каждая строка PowerShell ниже написана так, как вы набрали бы её в корне папки
LocalCanvas.

---

## 1. Установка

На компьютере, который будет генерировать:

| Что нужно | Зачем |
|---|---|
| **Windows 10 или 11** | Сторона компьютера в v0.2 — только Windows. |
| **Уже работающий ComfyUI**, с GPU | LocalCanvas запускает *ваши* воркфлоу; он не заменяет ComfyUI. |
| **PowerShell 7 или новее** (`pwsh`) и **Python 3.10 – 3.13** | `LocalCanvas.exe` сам проводит первоначальную настройку в открытом им же окне PowerShell (раздел 2), и настройка собирает собственное окружение LocalCanvas на найденном Python — оба инструмента лично вам открывать не придётся. Windows PowerShell 5.1 не поддерживается. `winget install --id Microsoft.PowerShell` или <https://aka.ms/powershell>; Python — с <https://www.python.org/downloads/>. |
| **Google Chrome или Microsoft Edge** | Только чтобы конвертировать воркфлоу, сохранённые в ComfyUI через **Save**. Воркфлоу, экспортированным через **Export (API)**, браузер не нужен. |
| **Телефон на Android** в том же Wi-Fi | То, чем вы, собственно, будете пользоваться. **Android 7.0 (API 24)** или новее — этот минимум объявляет релизная сборка. |
| **git** — или **Flutter** и **Android SDK** | Только для командной строки (раздел 14), которая клонирует репозиторий вместо скачивания zip-архива, либо чтобы собрать приложение для Android самому (раздел 5). |

Если на машине стоит несколько Python, выбирать не нужно: setup сам берёт
интерпретатор из поддерживаемого диапазона и печатает, какой он выбрал и какую
версию получил.

**Что проверялось.** Публичный CI (GitHub Actions, `windows-latest`, без
настоящего ComfyUI) гоняет тесты шлюза на Python 3.10 и 3.13, `flutter analyze`
и `flutter test` для приложения, тесты скриптов PowerShell и собственные тесты
лончера на .NET — на каждый push в `main` и каждый pull request. Вручную
сопровождающий проверил подключение и генерацию на одном складном телефоне по
Wi-Fi с настоящим ComfyUI; автоматически этот путь не покрыт ничем. Отправка
картинки или видео с телефона пока не подтверждена как работающая. Перевод
промпта, обнаружение по mDNS на телефоне и проверка брандмауэра в doctor с
правами администратора проверялись только на имитациях. Из профилей bootstrap
ComfyUI проверен только Minimal (ниже). Трей-лончер не проверялся целиком на
компьютере с выключенным Smart App Control — на компьютере самого
сопровождающего он включён, — так что сам путь через EXE не проверен от
начала до конца; на практике сопровождающий пользуется командной строкой
(раздел 14).

### Скачать и распаковать

Со страницы **Releases** этого репозитория: `LocalCanvas-0.2.0-windows-x64.zip`.
Распакуйте его куда угодно на компьютере — папка, в которую вы его распаковали,
и есть место, где LocalCanvas будет жить дальше; больше ничего на машине не
трогается. Внутри — одна папка `LocalCanvas`, а в ней `LocalCanvas.exe` рядом с
`scripts\`, `config\` и всем остальным, что ему нужно. `LocalCanvas.exe` должен
оставаться именно в этой папке: вынесенный из неё, он отказывается запускаться
и называет папку, в которой ожидает себя найти.

Архив самодостаточен: `LocalCanvas.exe` не нуждается в установленном .NET на
машине, которая его запускает. PowerShell 7 и Python (выше) всё равно нужны —
LocalCanvas собирает на них собственное окружение при первом запуске
(раздел 2).

### Где взять ComfyUI

**Он у вас уже есть — обычный случай.** Делать нечего. LocalCanvas никогда не
пишет в ComfyUI, который он не устанавливал, не добавляет пакетов в его Python
и не правит его конфигурацию. Единственная связь между ними — HTTP.

**Его у вас нет — необязательный bootstrap.**

```powershell
pwsh .\comfy\setup.ps1 -Profile Minimal -DryRun
pwsh .\comfy\setup.ps1 -Profile Minimal
```

(Запустите из окна PowerShell 7 внутри распакованной папки `LocalCanvas`, или
из клона, если вы на пути через командную строку.) Пробный прогон печатает
каждое действие, которое он бы совершил, и не пишет вообще ничего — ни одной
папки. Настоящий прогон клонирует ComfyUI на закреплённой ревизии (около 7 MiB
передаётся, около 31 MiB на диске) и создаёт его папку
`user/default/workflows`. Запустите дважды — второй прогон скажет, что всё уже
готово, и ничего не изменит.

**Куда он ставится.** Без `-ComfyRoot` корень будет
`%LOCALAPPDATA%\LocalCanvas\comfyui` — на обычной машине это
`C:\Users\<you>\AppData\Local\LocalCanvas\comfyui`. Внутри:

| Что | Где |
|---|---|
| Checkout ComfyUI — тот ComfyUI, о котором спросит раздел 2 | `<root>\ComfyUI` |
| Ваша папка воркфлоу, которую раздел 2 находит сам | `<root>\ComfyUI\user\default\workflows` |
| Запись о том, что было установлено | `<root>\localcanvas-bootstrap.json` |

Чтобы положить всё в другое место, передайте `-ComfyRoot "D:\somewhere"`.
Набирать эти пути заново не придётся: setup предложит это место ответом на
вопрос *где ваш ComfyUI* (раздел 2), и достаточно нажать Enter. Если хотите
прочитать их заранее, пробный прогон печатает их целиком: строка `Root:`
сверху, затем по строке `[PLAN]` на каждое действие, а в заключительном блоке
повторяются **checkout ComfyUI и запись об установке**; папка воркфлоу стоит в
плане выше, а не в этом блоке.

Папка `user/default/workflows` существует с того момента, как bootstrap
закончил работу, поэтому импорту из раздела 6 есть что читать ещё до того, как
вы сохранили хоть один воркфлоу.

**Чего он не делает, прямым текстом:** он не скачивает моделей и не собирает
окружение Python. Прежде чем этот ComfyUI запустится, вам ещё предстоит самому
поставить поддерживаемый Python, установить собственный `requirements.txt`
ComfyUI (несколько гигабайт, и выбрать сборку CUDA под вашу видеокарту — ваше
решение), добыть модели, которые нужны вашим воркфлоу, и запустить ComfyUI.

В v0.2 поддерживается только профиль **Minimal**. Формат манифеста описывает
также профили Recommended и Video; они экспериментальные, для этого выпуска не
проверялись, и ни под одним из них LocalCanvas не поставляет моделей.

Чтобы спросить, будет ли ComfyUI — ваш или поставленный bootstrap'ом — работать
с LocalCanvas:

```powershell
pwsh .\comfy\doctor.ps1
```

Он только читает, и каждый ответ получен настоящим запросом к работающему
ComfyUI. Он выходит с кодом **0** (COMPATIBLE), **2** (UNKNOWN — ничего не
упало, но хотя бы одну проверку сделать не удалось) или **3**
(NOT COMPATIBLE). Проверка, которую не удалось сделать, никогда не выдаётся за
пройденную, поэтому незапущенный ComfyUI даёт UNKNOWN, а не справку о здоровье.

## 2. Первый запуск

Дважды щёлкните `LocalCanvas.exe` внутри распакованной папки `LocalCanvas`.

**Если настройка ещё не выполнялась** — нет `.venv\Scripts\python.exe` или
нет `config\local\runtime.yaml` — появится диалог:

> **LocalCanvas setup is required before first use.**
>
> Setup runs scripts\setup.ps1 in a PowerShell window. LocalCanvas continues
> when it has finished.
>
> **[Run setup]** [Cancel]

Выберите **Run setup**. Откроется видимое окно PowerShell с запущенным
`scripts\setup.ps1` — тем же скриптом, который использует командная строка
(раздел 14), так что вопросы будут ровно те же, что при запуске из трея и что
при ручном запуске.

### Два вопроса

1. **«Вы запускаете ComfyUI сами или это должен делать LocalCanvas?»**
   Спрашивается первым, потому что ответ решает, что ещё понадобится.
   Варианты предлагаются как `1  I start ComfyUI myself` и
   `2  LocalCanvas starts ComfyUI for me`, и **1** — это то, что даёт Enter.
   * **1 — внешний режим.** LocalCanvas никогда не запускает ComfyUI и никогда
     его не останавливает; он лишь проверяет, что адрес отвечает, прежде чем
     поднять шлюз. Никакую команду запуска вычислять не нужно — поэтому этот
     режим требует от вас меньше всего.
   * **2 — управляемый режим.** LocalCanvas может запустить ComfyUI за вас,
     использует уже запущенный вместо второго и останавливает только тот,
     который запустил сам. Запускает он его тем Python, который уже лежит
     рядом с вашим ComfyUI — `python_embeded\python.exe` у портативной сборки,
     `venv\Scripts\python.exe` или `.venv\Scripts\python.exe` у клона, — и эти
     значения setup считывает с установки и пишет в `comfy.launcher`. В этот
     интерпретатор он ничего не устанавливает. Если его нет, setup
     **отказывается**, а не угадывает, и называет внешний режим как путь
     дальше.
2. **«Где ваш ComfyUI?»** Папка, в которой лежит `main.py`, или папка, в
   которой лежит *эта* папка, — для портативной сборки. Обе раскладки
   распознаются, а введённое вами проверяется. Вот это вывести неоткуда:
   LocalCanvas не сканирует диски, не обходит дерево каталогов и не читает
   реестр. Если вы поставили ComfyUI bootstrap'ом из раздела 1, его место
   предлагается по умолчанию — достаточно нажать Enter.

**Третий** вопрос задаётся только тогда, когда `user\default\workflows` —
собственное место ComfyUI для воркфлоу — не лежит внутри названной вами папки.
Когда оно там, оно находится само и ничего не спрашивается.

Больше ничего не спрашивается, потому что больше ничего и не нужно: имя для
показа берётся из имени компьютера, адрес ComfyUI — из собственного значения
ComfyUI `127.0.0.1:8188`, адрес шлюза — `0.0.0.0:7801`.

Пишутся два файла, оба в `config\local\`, которая в gitignore, поэтому ваши
пути никогда не попадут в коммит: `config\local\runtime.yaml` (режим, ваш
ComfyUI, адреса, имя этого компьютера для показа) и
`config\local\workflow-sources.yaml` (та самая папка, из которой LocalCanvas
читает ваши воркфлоу).
[`config/examples/runtime.example.yaml`](../config/examples/runtime.example.yaml) —
справочник по всему, что может быть в `runtime.yaml`.

### Когда настройка закончена

Окно печатает пустую строку и **«Press Enter to close this window.»** —
прочитайте, нажмите Enter, окно закроется. Дальше LocalCanvas продолжает сам:

- **Настройка прошла успешно** — он идёт дальше сам: запускает ComfyUI (или
  проверяет, что ваш внешний отвечает), проверяет папку воркфлоу и запускает
  шлюз.
- **Настройка не прошла** — в трее появляется **Could not start**, а диалог с
  заголовком **«Setup did not finish.»** называет причину (окно не удалось
  открыть, оно завершилось с кодом выхода, или оно закончилось, но LocalCanvas
  всё равно не настроен) и предлагает запустить `scripts\setup.ps1` самому,
  чтобы увидеть, чего не хватает. Ничего не было запущено.

Если вместо этого выбрать **Cancel** на первом диалоге, ничего не запускается,
и LocalCanvas завершает работу.

**Пока настройка не выполнена хотя бы раз, этот диалог не появится больше** —
следующий двойной щелчок идёт прямо к ежедневному запуску (раздел 3).

### Воркфлоу при первом запуске

Если в вашей папке воркфлоу нашлось что-то новое, появится:

> **N workflow changes detected.**
>
> Sync now imports them before the Gateway starts. Later starts LocalCanvas on
> the workflows it already has; nothing is changed.
>
> **[Sync now]** [Later]

Что значит «синхронизировать» и что происходит с воркфлоу, который LocalCanvas
не может прочитать уверенно, — в разделе 6. Когда шлюз поднялся, значок в трее
становится зелёной галочкой: LocalCanvas готов. Поставьте приложение на телефон
(раздел 5) и откройте **Open status** в трее (раздел 4) — там адрес и QR-код
для сопряжения.

## 3. Ежедневный запуск

Просто дважды щёлкните `LocalCanvas.exe` ещё раз — это всё. На один сеанс
входа в Windows приходится не больше одного LocalCanvas: повторный двойной
щелчок, пока первый экземпляр ещё работает, никогда не запускает второй. Он
просит первый экземпляр вывести окно **Open status** на передний план и
завершается, не выполнив ни одного скрипта.

Значок в трее проходит одни и те же состояния при каждом запуске:

| Значок | Состояние | Подсказка говорит |
|---|---|---|
| Янтарный диск с открытой дугой-спиннером | Starting | `LocalCanvas — Starting…` |
| Зелёный диск с галочкой | Ready | `LocalCanvas — Ready` |
| Янтарно-жёлтый треугольник с «!» | Готов, но воркфлоу нужно посмотреть | `LocalCanvas — Ready (N workflows need a look)` |
| Красный диск с «x» | Шлюз недоступен, или запуск не удался | `LocalCanvas — Gateway down` / `LocalCanvas — Could not start` |
| Просто серый диск | Stopping (идёт Exit) | `LocalCanvas — Exiting…` |

Если уже запущенный шлюз всё ещё правильно отвечает, он используется повторно
вместо нового запуска — то же верно и для ComfyUI в управляемом режиме, и для
ComfyUI, который вы уже запустили сами во внешнем режиме. LocalCanvas никогда
не запускает вторую копию ни того, ни другого.

Пока LocalCanvas в состоянии Ready, шлюз и ComfyUI проверяются каждые 5 секунд
(таймаут 2 секунды, без прокси). Две неудачные проверки шлюза подряд — то есть
примерно через 14 секунд после того, как он действительно исчез, — делают
значок красным и переводят LocalCanvas в состояние *Gateway down*;
автоматического перезапуска нет. В первый раз, когда это случается, вы получите
одно уведомление:

> **Gateway down**
>
> The LocalCanvas Gateway stopped. Right-click the tray icon and choose
> Restart Gateway.

— один раз на каждый случай, когда шлюз падает, а не на каждую неудачную
проверку после этого. Полное меню трея, включая **Restart Gateway**, — в
разделе 4.

## 4. Трей

Правая кнопка по значку открывает меню, всегда в этом порядке:

    LocalCanvas                       (жирным, не нажимается)
    Gateway: <статус>
    ComfyUI: <статус>
    Workflows: <статус>
    ───────────────────────
    Restart Gateway
    Sync workflows
    Open status
    ───────────────────────
    Exit

Двойной щелчок по значку сразу открывает **Open status**.

**Три строки статуса**, взятые прямо из работающего LocalCanvas:

- **Gateway:** `Starting…`, `Ready`, `Restarting…`, `DOWN`, `Stopping…` или
  `Not running`.
- **ComfyUI:** `Ready`, `Down`, `Starting…` или `Unknown`, с приставкой
  `(external)`, если LocalCanvas не запускал его сам — использованный повторно
  или по-настоящему внешний, в обоих случаях он не будет остановлен за вас
  (раздел 15).
- **Workflows:** число, с приставкой `(N need a look)`, если что-то требует
  внимания, `(check did not complete)`, если сама проверка не удалась, или
  `(no folder configured)`, если папка ещё не настроена.

**Restart Gateway** и **Sync workflows** доступны только когда LocalCanvas
в состоянии Ready, показывает, что воркфлоу нужно посмотреть, или когда шлюз
недоступен, — никогда во время старта, перезапуска, синхронизации или выхода.
Пока шлюз недоступен, **Restart Gateway** показан **жирным** — это первое, что
стоит попробовать.

**Форма значка**, а не только цвет, говорит, в каком вы состоянии: **зелёный
диск с галочкой** (Ready); **янтарный диск с открытой дугой-спиннером**
(Starting, Restarting); **янтарный диск с двумя круглыми стрелками**
(Syncing); **янтарно-жёлтый треугольник с «!»** (воркфлоу нужно посмотреть —
сам шлюз в порядке); **красный диск с «x»** (шлюз недоступен, либо сам запуск
не удался — в обоих случаях телефон прямо сейчас не может пользоваться
LocalCanvas); **простой серый диск** (Stopping).

### Open status

Небольшое окно с местом на большее, чем в меню:

- **Gateway** — его статус, а пока он недоступен, рядом кнопка **Restart
  Gateway** (в остальное время скрыта).
- **Endpoint**, кнопка **Copy address** и QR-код для сопряжения — тот же
  адрес, к которому подключается телефон (раздел 5). QR-код генерируется по
  запросу; если его не удалось получить, показывается только адрес.
- **ComfyUI** — его статус.
- **Workflows**: сколько готово и сколько нужно посмотреть.
- Строка **problem**, только если она есть.
- **Log**, называющая `.runtime\launcher.log`, рядом кнопка **Open logs
  folder**.
- **Close** закрывает окно; LocalCanvas продолжает работать, а следующий
  **Open status** (или двойной щелчок) открывает то же самое окно, а не
  создаёт новое.

### Exit и подтверждения

**Exit** останавливает то, что запустил LocalCanvas, — через тот же `stop.ps1`,
которым пользуется командная строка (раздел 15), — а затем закрывает трей.
Внешний ComfyUI, или тот, который LocalCanvas только использовал повторно,
никогда не останавливается за вас.

Если шлюз сообщает, что генерация ещё идёт, и **Restart Gateway**, и **Exit**
сначала спрашивают, а не прерывают её без слов:

> **A generation may still be running. Restart the Gateway anyway?**
>
> **[Restart]** [Cancel]

(для Exit: **«...Exit LocalCanvas anyway?»**, с **[Exit]** и **[Cancel]** —
по умолчанию в обоих случаях Cancel). Если выбрать Cancel, всё останется
работать без изменений. С того момента, как начался Exit — даже если ещё не
закончился какой-то более ранний вызов, — подсказка в трее уже говорит
`LocalCanvas — Exiting…`.

Если LocalCanvas не смог убедиться, что всё запущенное им действительно
остановилось, диалог с заголовком **«LocalCanvas could not stop everything it
started.»** называет, что сейчас или, возможно, всё ещё работает, и указывает
на `status.ps1` и `stop.ps1` (раздел 15), чтобы проверить и закончить дело
руками.

## 5. Подключение телефона

### Установка приложения

В самом репозитории APK нет. Если репозиторий публикует релиз, проще всего
взять APK на его странице **Releases**: скачайте
`LocalCanvas-0.1.5-arm64-v8a.apk` и установите, как описано ниже, — в этом
выпуске приложение не изменилось, поэтому его собственная версия остаётся
0.1.5, даже когда сторона Windows перешла на 0.2.0. Иначе соберите сами.

**Собрать самому**, из `app/`:

```powershell
flutter pub get
flutter build apk --release --split-per-abi
```

Если Flutter на машине ещё нет, **начните с собственного руководства Flutter
для Windows** — <https://docs.flutter.dev/get-started/install>: оно ставит
SDK и проводит вас по части, относящейся к Android (Android Studio приносит
Android SDK с собой). Это самый долгий шаг в этом руководстве и единственный,
где ставится целый инструментарий, а не одна программа.

Дальше `flutter doctor` перечислит, чего ещё не хватает, а
`flutter doctor --android-licenses` — тот однократный шаг, который принимает
лицензии Android SDK: это соглашение между вами и Google, поэтому ни один
скрипт здесь не делает этого за вас. Когда `flutter doctor` доволен
инструментарием Android, две команды выше заработают.

APK появляются в `app/build/app/outputs/flutter-apk/`, по одному на ABI, каждый
с именем `LocalCanvas-<version>-<abi>.apk`; большинству телефонов нужен
`arm64-v8a`. Установите один из них через `flutter install`, `adb install` или
просто скопировав файл на телефон — в последнем случае Android спросит,
разрешаете ли вы установку из той программы, которой вы его скопировали: это
ручная установка, а не установка из магазина.

**Сборки из CI.** Workflow **APK** в репозитории (`.github/workflows/apk.yml`)
выполняет ту же сборку при каждом push в `main` и по запросу. Если вам виден
его запуск, артефакт **`LocalCanvas-apk-debug-signed`** внизу страницы запуска —
это zip с тремя APK. Артефакты хранятся **14 дней**, так что ссылку на них не
сохраняйте.

**Любой APK отсюда подписан отладочным ключом.** Подпись релиза в проекте не
настроена, поэтому у релизного типа сборки стоит отладочная конфигурация
подписи, и каждая сборка — ваша или из CI — подписана отладочным ключом
Android. Это сборка для ручной установки: не проверенный и не распространяемый
релизный артефакт, ничем не подписанный от имени проекта и не более
заслуживающий доверия, чем тот, что вы соберёте сами. Отладочный ключ
генерируется на каждой машине свой, и следующий запуск его не повторяет,
поэтому установка более нового APK поверх старого, собранного в другом месте,
может не пройти с ошибкой `INSTALL_FAILED_UPDATE_INCOMPATIBLE` — сначала
удалите LocalCanvas, а вместе с ним уйдут и сохранённые в приложении
настройки: если они вам дороги, сначала экспортируйте профиль (раздел 11).

### Подключение

Откройте приложение, когда компьютер работает. Есть четыре пути внутрь, ни
один из них не главный, и все они заканчиваются одним и тем же рукопожатием,
прежде чем адрес будет принят:

1. **Запомненный сервер** — последний работавший адрес пробуется при запуске.
2. **«В этой сети»** — шлюз объявляет себя по mDNS, а приложение показывает то,
   что нашло. Некоторые роутеры и VPN не пропускают multicast; это нормальный
   исход, и приложение просто предлагает остальные три пути.
3. **«Сканировать код подключения»** — тот QR-код из **Open status** в трее
   (раздел 4) или из собственного окна `start.ps1` на пути через командную
   строку (раздел 14). Всё происходит локально: ни сервиса QR, ни сокращателя
   ссылок, ни секрета внутри кода.
4. **«Ввести адрес»** — предлагается всегда. `192.0.2.42`, `192.0.2.42:7801`
   и `http://192.0.2.42:7801` работают одинаково (с адресом вашего
   компьютера); порт по умолчанию — 7801.

Если по адресу кто-то отвечает, но это не LocalCanvas или он говорит на другой
версии API, приложение скажет, что именно и что с этим делать.

**Брандмауэр Windows — самое вероятное препятствие.** Шлюз — это новая
программа, слушающая порт, а Windows не пускает к ней из сети, пока
кто-нибудь это не разрешит. При первом запуске шлюза LocalCanvas должно
появиться окно *Брандмауэр Защитника Windows*: отметьте **частные сети**
(Private), но не общедоступные — у шлюза нет аутентификации, и ему место
только в вашей собственной локальной сети. Если окна не было или его закрыли,
на компьютере всё по-прежнему выглядит правильно, а телефон всё равно не
достучится: QR-код сканируется, адрес верен, соединение отваливается по
таймауту.

`pwsh .\scripts\doctor.ps1` (раздел 14) сообщает о порте шлюза и о том,
слушает ли его кто-нибудь. Сами правила брандмауэра он читает только при
запуске с правами администратора — без повышения прав, а это и есть
описанный способ запуска, он пишет *not measured, needs Administrator*, а не
гадает. Исправить или проверить существующее правило вручную можно в оснастке
Windows **Брандмауэр Защитника Windows в режиме повышенной безопасности**, а
в [`privacy-security.md`](privacy-security.md) описан необязательный
`scripts\strict-lan.ps1`, который идёт дальше и обратим.

## 6. Добавление и обновление воркфлоу

Setup уже написал `config/local/workflow-sources.yaml` и указал в нём папку
воркфлоу вашего ComfyUI — при обычной установке это `user/default/workflows`
внутри папки ComfyUI. Этот файл — целиком два обещания: **папки, которые вы
перечислили, — единственные папки, которые LocalCanvas вообще читает**, и
**ваши файлы воркфлоу он только читает** — ничто их не переименовывает, не
перемещает, не удаляет и не переписывает.

### Save или Export (API) — годится и то и другое

ComfyUI записывает воркфлоу в одном из двух видов, и LocalCanvas принимает
оба:

| В ComfyUI вы использовали | Что с ним делает LocalCanvas |
|---|---|
| **Save** (обычный способ) | При импорте конвертирует его через ваш же запущенный ComfyUI, в Chrome или Edge, который уже стоит на компьютере. |
| **Workflow → Export (API)** (в старых ComfyUI — *Save (API Format)*) | Импортирует как есть. Браузер не нужен. |

Так что от воркфлоу, сохранённого через **Save**, требуется только одно: **во
время импорта ComfyUI запущен, а Chrome или Edge установлен.** Браузер
работает без окна, с собственным одноразовым профилем, поэтому на экране
ничего не появляется.

### Повседневный порядок, из трея

1. Создайте или измените воркфлоу в ComfyUI и сохраните его в свою папку
   воркфлоу.
2. При запущенном ComfyUI (если только вы не поручили его запуск LocalCanvas)
   запустите LocalCanvas или оставьте его работающим — в любом случае он
   смотрит в вашу папку перед запуском, либо вы просите его посмотреть через
   **Sync workflows**, пока он уже работает.
3. Изменение, найденное при запуске, предлагается диалогом **«N workflow
   changes detected.»** (раздел 2); в любой другой момент нажмите правой
   кнопкой на значок в трее и выберите **Sync workflows** сами. В обоих
   случаях пройдёт импорт, и, если хотя бы одно определение действительно
   было записано, LocalCanvas сам перезапустит шлюз после этого, чтобы
   телефон увидел новый воркфлоу, — шлюз читает каталог один раз, при запуске,
   и это тот самый момент, который имеет значение.
4. Когда всё готово, появляется сводка: **«Workflow sync completed.»** /
   `Updated: N · Needs review: N`.
5. Если приложение уже было открыто, а воркфлоу в списке нет, нажмите
   **«Обновить список»** (↻) вверху экрана **«Выбрать воркфлоу»**.

В фоне за папкой никто не следит. Изменение подхватывается при следующем
запуске, по **Sync workflows** или запуском импорта из командной строки
(раздел 14) — и никогда само по себе.

### Когда воркфлоу не удалось импортировать

Воркфлоу, сохранённый через **Save**, который не удалось конвертировать,
обрабатывается в зависимости от того, *почему*:

- **Будет предложен снова.** Если конвертацию не удалось даже начать — нет
  Chrome или Edge либо ComfyUI не был готов, — следующая проверка предложит
  его снова, в составе числа изменений. Устраните причину (запустите ComfyUI,
  установите браузер) и синхронизируйте снова.
- **Нужно посмотреть.** Если ComfyUI отказался конвертировать этот граф или
  LocalCanvas не смог уверенно прочитать сконвертированный граф, строка
  Workflows в трее говорит `(N need a look)`, пока файл не изменится. Пробный
  прогон из командной строки (раздел 14) называет каждый и причину; исправьте
  его в ComfyUI и сохраните снова — изменённый файл будет предложен снова, как
  любой другой.

Воркфлоу, который LocalCanvas уже импортировал, повторно не упоминается, пока
он не изменится. **Воркфлоу, который вы удалили из папки ComfyUI**, при каждой
проверке упоминается как `no longer in your folder`. **Из каталога никогда
ничего не удаляется автоматически** — `detect_removed: false` в
`config/local/workflow-sources.yaml` отключает это сообщение, для папки,
которая лежит на диске, который подключён не всегда.

### Написать определение самому

**Воркфлоу, который нельзя прочитать уверенно, откладывается, а не
угадывается.** Он помечается `NEEDS_REVIEW` с предложением, называющим, что
именно не удалось решить — для графа это узел и вход, — и определение для
него не пишется. Все остальные воркфлоу импортируются как обычно, а
переключателя «импортировать всё равно» нет. Выхода два, и какой лучше,
зависит от этого предложения:

1. **Изменить воркфлоу так, чтобы вопрос исчез.** Часто это узел,
   использованный так, что импорт не может прочитать его как вход, —
   переподключите или замените его в ComfyUI, сохраните и синхронизируйте
   снова.
2. **Написать это одно определение самому.** Определение — небольшой
   YAML-файл в `config/local/workflows` рядом со сгенерированными: формат
   описан в [`workflow-schema.md`](workflow-schema.md), а в
   [`../workflows/examples/`](../workflows/examples/) лежат три полных
   разобранных примера — только промпт, вход-картинка и вход-видео, — с
   которых можно списать. Определение, написанное вами, импорт не трогает.

**Сгенерированное определение тоже ваше — правьте.** Следующая синхронизация
перепишет его, только если изменился стоящий за ним воркфлоу, и сохранит имя,
представление, настройку перевода и каждую подпись и подсказку, которые вы
написали. Чтобы вернуть сгенерированные, `sync-workflows.ps1 -RegenerateLabels`
(раздел 14).

Проверьте папку перед перезапуском шлюза — без ComfyUI, GPU и сети:

```powershell
.\.venv\Scripts\python.exe -m localcanvas_gateway.workflows config\local\workflows
```

    [ OK ] my-portrait (11 fields) - config\local\workflows\my-portrait.yaml
    2 workflows loaded, 0 rejected, from config\local\workflows

Отклонённое определение называется вместе с файлом, воркфлоу и проблемой;
остальные всё равно загружаются.

## 7. Генерация

Выберите воркфлоу — и приложение нарисует форму, которую этот воркфлоу
объявил. Напишите промпт, заполните остальное, о чём он просит, нажмите
**«Сгенерировать»**.

Пока идёт работа, вы видите честные состояния — отправка, ожидание в очереди,
генерация — с настоящим прогрессом там, где его сообщает бэкенд, и с
неопределённым индикатором там, где не сообщает. Никаких выдуманных
процентов. **«Остановить»** есть там, где воркфлоу это поддерживает.

Результат открывается крупно. Его можно посмотреть почти на весь экран,
**«Сохранить»** в галерею, **«Поделиться»** через системный лист Android и
нажать **«Сгенерировать снова»**.

**«Сгенерировать снова» и seed.** Приложение меняет seed у каждого поля, роль
которого — seed, и вписывает новое число в поле, так что seed на экране —
всегда тот seed, который был отправлен. Больше в форме не меняется ничего. В
«Дополнительно» есть переключатель **«Зафиксировать seed»**, по умолчанию
выключенный: с ним «Сгенерировать снова» берёт тот же seed.

Переход по результатам этого сеанса — маленькое состояние в памяти:
ограниченный список, байты не хранятся, ничего не записывается, и после
закрытия приложения не остаётся ничего. Ни галереи, ни истории в базе данных
нет — так решено.

### Работа с картинкой или видео

Воркфлоу, определение которого объявляет вход-картинку или вход-видео,
показывает выбор файла. Выберите фотографию или видео, посмотрите на превью,
замените его или уберите и следите за настоящим прогрессом в байтах во время
отправки.

**Фотографии HEIC обрабатываются за вас.** Современные камеры Samsung и iPhone
по умолчанию сохраняют в HEIC. LocalCanvas смотрит на *байты* файла, а не на
его имя, и превращает фотографию HEIC или HEIF в JPEG **на телефоне**, до
отправки. Любой другой файл проходит байт в байт — PNG сохраняет прозрачность,
JPEG не перекодируется. Если на телефоне нет декодера HEIF или декодирование
не удалось, отправляется оригинал, а шлюз отказывает с сообщением, называющим
формат (раздел 13).

**Видеорезультаты** получают локальное превью и воспроизведение, а также
«Сохранить» и «Поделиться». Большие файлы отправляются дольше;
`media.max_video_megabytes` в `config/local/runtime.yaml` — предел, который
проверяет шлюз, и сообщение об отказе его называет.

Отправленные файлы лежат во временном хранилище на компьютере со своим сроком
жизни (`media.ttl_seconds`, по умолчанию час). Генерация, которая ссылается на
уже истёкший файл, скажет об этом и попросит его заново, а не завалится
непонятным образом.

## 8. Основное и «Дополнительно»

Каждый воркфлоу показывает сначала те немногие поля, которые важны, а
остальные держит за **«Дополнительно»**. Что куда попало — из определения
воркфлоу, а не из догадок приложения: приложение понимает *типы* полей и их
*представление* и ничего не знает про модели, чекпойнты и графы узлов.
Группировка — тоже конфигурация: названия разделов берутся из ваших
определений, а незнакомая группа рисуется своим разделом. Фильтр над
карточками воркфлоу сужает список до одной группы или возвращает к **«Все»**.

## 9. Мои значения, черновики и наборы

Три разные вещи, и это намеренно:

- **Мои значения по умолчанию** — *что я хочу всегда?* **«Сохранить настройки
  как мои значения»** запоминает текущие значения для этого воркфлоу;
  **«Сбросить настройки к моим значениям»** возвращает их, а **«Сбросить
  настройки к значениям воркфлоу»** возвращает к тому, что объявил автор
  определения.
- **Черновики** — *на чём я остановился?* Один на воркфлоу, сохраняется сам и
  перезаписывается. Он возвращает ваш текст и настройки; медиаполе намеренно
  возвращается пустым, потому что к моменту повторного чтения черновика
  идентификатор отправленного файла обычно уже истёк, и форма просит картинку
  заново.
- **Наборы** — названные сочетания, которые вы решили сохранить. Сохраните
  настройки отдельно или промпт вместе с настройками, а потом называйте,
  переименовывайте и забывайте их.

## 10. Промпт на своём языке

По желанию, по умолчанию выключено, и работает на вашем компьютере. Если
`prompt_translation` в `config/local/runtime.yaml` включён, промпт, написанный
на языке, который вы перечислили в `sources`, переводится на `target` до
того, как будет собрана генерация. Распознавание идёт по письменности: промпт
без кириллицы и без каны остаётся ровно таким, каким вы его набрали. Всё, что
стоит внутри `"двойных кавычек"`, переводчику не отдаётся никогда, поэтому
вывеска или имя останутся как написаны.

Этому нужна отдельная установка, примерно на гигабайт, в собственный `.venv/`
LocalCanvas и нигде рядом с ComfyUI, плюс по одной языковой паре на каждый
язык, на котором вы пишете. `--editable` важен: шлюз остаётся установленным из
этого checkout, так же, как его установил setup.

```powershell
.\.venv\Scripts\python.exe -m pip install --editable ".\gateway[translation]"
.\.venv\Scripts\argospm.exe update
.\.venv\Scripts\argospm.exe install translate-ru_en
```

Во время генерации не скачивается ничего: эта установка — единственная
загрузка, и она происходит потому, что вы о ней попросили. Те же команды есть
в комментариях рядом с блоком `prompt_translation` в
`config/examples/runtime.example.yaml`, где разобраны и остальные настройки.
Включение без установки не проваливается молча: приложение говорит, чего не
хватает, ещё до того, как вы нажмёте «Сгенерировать», а промпт, который нужно
перевести, сообщает, какой именно установки нет. Какие пары у вас есть,
читается при запуске шлюза и печатается в его выводе (`Translation: ru->en`),
поэтому пару, установленную на ходу, шлюз подхватит при следующем перезапуске —
через **Restart Gateway** в трее или следующий `start.ps1`.

Ваш исходный текст — это всегда то, что показывает приложение, что хранит
черновик и что переотправляет «Сгенерировать снова». Перевод никогда не
заменяет ваших слов.

## 11. Переезд на другой телефон

**Ваш профиль** — это ваши сохранённые настройки и наборы одним файлом.
Экспортируйте его, перенесите файл как вам удобно и импортируйте на другом
телефоне. В нём нет ничего о сервере и ничего из того, что вы сгенерировали, а
импорт ничего не удаляет из уже имеющегося — чтобы применить импортированное,
нажмите **«Сбросить настройки к моим значениям»**. Оформление и язык
приложения принадлежат устройству и намеренно в профиль не входят. Профиль,
записанный более новым LocalCanvas, отвергается по имени, а не читается
наполовину.

## 12. Статус и восстановление

**На компьютере.** Три строки статуса в трее и **Open status** (раздел 4) —
повседневный способ увидеть, что LocalCanvas думает о происходящем. После
того как LocalCanvas перешёл в Ready, шлюз и ComfyUI проверяются каждые 5
секунд (таймаут 2 секунды); две неудачные проверки шлюза подряд — примерно 14
секунд — и есть то, что делает значок красным. Само по себе ничего не
перезапускается; **Restart Gateway** — это осознанное действие, которое всегда
остаётся за вами. Командная строка даёт ту же информацию без трея:
`pwsh .\scripts\status.ps1` только читает и сообщает, что запущено, что
принадлежит LocalCanvas и какой у него адрес; `pwsh .\scripts\doctor.ps1`
ставит диагноз всей машине сразу (раздел 13).

**На телефоне.** Если Wi-Fi обрывается посреди генерации, приложение
переподключается само — от 1 до 10 попыток, по умолчанию 3, настраивается для
каждого устройства, — а потом спрашивает у шлюза, уцелела ли задача. Если
определить не удаётся, оно так и говорит, а не гадает: задача, которая
закончилась, пока вы были отключены, — не то же самое, что задача, которая
вообще не выполнялась.

## 13. Когда что-то не так

**`[Cancel]` на диалоге о необходимой настройке, или настройка, которая не
закончилась.** В обоих случаях ничего не было запущено. Cancel оставляет
LocalCanvas завершённым; настройка, которая не закончилась, показывает
**«Setup did not finish.»**, называя причину, и предлагает
`pwsh .\scripts\setup.ps1` из окна PowerShell 7, чтобы увидеть, чего не
хватает, напрямую (раздел 2).

**Остался работать шлюз от версии до v0.2.0.** Обновление при работающем
старом шлюзе LocalCanvas отклоняется, а не тихо используется повторно:
`start.ps1` (а значит, и трей) сообщает `Port 7801 is already in use` и
называет решение — `pwsh .\scripts\stop.ps1 -Component Gateway` — остановите
его один раз и запустите снова.

**Smart App Control блокирует `LocalCanvas.exe` без вариантов.** На
компьютере с включённым Smart App Control Windows отказывается запускать
неподписанный исполняемый файл — диалога «Запустить всё равно» не будет.
`LocalCanvas.exe` не подписан. Воспользуйтесь путём через командную строку
(раздел 14): он идёт через `pwsh`, который подписан Microsoft и этим не
затронут. Выключение Smart App Control — настройка Windows Security на этом
компьютере, а не то, что может сделать за вас LocalCanvas, и это руководство
не советует ни того, ни другого.

**Windows блокирует скрипт, скачанный внутри zip-архива («cannot be loaded»
или предупреждение безопасности про зону интернета).** Файлы, распакованные
из архива, скачанного из интернета, несут метку загрузки (Mark of the Web).
`LocalCanvas.exe` сам запускается независимо от неё; а вот скрипт,
запускаемый прямо из PowerShell, может отказаться. Снимите её один раз,
внутри распакованной папки `LocalCanvas`:

```powershell
Get-ChildItem -Recurse | Unblock-File
```

**Скрипт отказывается запускаться: «cannot be run because it contained a
`#requires` statement».** Вы запускаете его в Windows PowerShell 5.1 — эту
оболочку LocalCanvas не поддерживает: всем скриптам здесь нужен PowerShell 7
или новее, а сам `LocalCanvas.exe` ищет только `pwsh.exe` и никогда
`powershell.exe`. Если PowerShell 7 не найден вовсе, об этом говорится ещё до
того, как что-либо запущено: **«PowerShell 7 is required. Install PowerShell
7 and start LocalCanvas again.»**, с решением `winget install --id
Microsoft.PowerShell --source winget`. Если вместо этого вы запускаете
скрипт руками и видите отказ про `#requires`, это сообщение выдаёт сама
Windows, поэтому оно приходит на языке вашей системы, переносится по ширине
окна (номера версий в нём могут разорваться на две строки) и называет
требование «Windows PowerShell 7.0» — такого продукта не существует. Нужен
PowerShell 7, его команда — `pwsh`. Посмотреть, где вы сейчас:

```powershell
$PSVersionTable.PSVersion
```

И ещё одно, если вы вызываете эти скрипты из собственного скрипта: отказ —
это ошибка, а не код возврата, поэтому проверяйте `$?`, а не `$LASTEXITCODE`.

**Сначала запустите доктора.**

```powershell
pwsh .\scripts\doctor.ps1
```

Он ничего не запускает, не пишет ни одного файла и ничего не меняет. Его код
возврата:

| Код | Что значит |
|---|---|
| **0** | Все проверки, которые он смог сделать, прошли чисто. |
| **2** | Ничего не упало, но хотя бы одну проверку не удалось сделать либо она вернулась предупреждением, на которое стоит отреагировать. Отсутствующая или нечитаемая конфигурация — тоже 2. |
| **3** | Что-то не прошло. |

На полном прогоне итоговый блок учитывает каждую проверку, и код возврата —
тот самый, из которого этот блок и получен. **Два отказа обрывают прогон
раньше и не печатают итогового блока вовсе**: ещё нет `.venv/` и
конфигурация, которую не удалось прочитать. Каждый печатает свою строку
`[FAIL]` с тем, что делать, и на этом останавливается, потому что ниже
диагностировать уже нечего: отсутствующее окружение даёт код 3, а нечитаемая
конфигурация — код 2, как и всюду здесь.

Чтобы прочитать фильтры портов брандмауэра, нужны права администратора. При
запуске без повышения прав — а именно так его и описано запускать — эта
проверка отмечается как *not measured, needs Administrator* и не превращает
чистый прогон в 2.

**Setup сообщает, что подходящего Python нет.** Установите Python 3.10 – 3.13
с <https://www.python.org/downloads/> и запустите настройку снова, либо
(путь через командную строку, раздел 14) укажите интерпретатор через
`-PythonExe`. Ничего создано не было.

**`start.ps1` пишет `ComfyUI is not reachable` и выходит с кодом 4.** ComfyUI
не запущен, или `comfy.host`/`comfy.port` в `config/local/runtime.yaml`
указаны неверно. Во внешнем режиме LocalCanvas никогда не запускает ComfyUI
за вас: запустите его и попробуйте снова.

**«Это фото в формате HEIC, который LocalCanvas пока не поддерживает.»**
Телефон не смог сам декодировать HEIC, поэтому до шлюза дошёл оригинал и был
отклонён. Выберите JPEG или PNG либо отключите в настройках камеры
высокоэффективный формат фото (HEIC).

**В приложении не хватает воркфлоу или их нет совсем.** При запущенном
ComfyUI синхронизируйте из трея либо выполните
`pwsh .\scripts\sync-workflows.ps1 -DryRun` (раздел 14) и прочитайте отчёт.
Воркфлоу, отмеченный как `NEEDS_REVIEW`, отложен, потому что что-то не
удалось решить уверенно, и строка говорит, что именно. Воркфлоу, отмеченный
как `NEEDS_API_EXPORT`, был сохранён через **Save**, и не нашлось запущенного
ComfyUI (или Chrome либо Edge), чтобы его сконвертировать, — устраните это и
синхронизируйте снова. Если вы синхронизировали при уже работающем шлюзе,
запущенном из командной строки, а не через трей, остановите и запустите его
снова: каталог он читает один раз, при запуске (трей делает этот перезапуск
за вас автоматически — раздел 6). Затем нажмите в приложении **«Обновить
список»**.

**При каждой проверке пишется `N workflow file(s) need a look`.** ComfyUI
отказался конвертировать эти файлы, или LocalCanvas не смог уверенно их
прочитать, или это вовсе не воркфлоу. `pwsh .\scripts\sync-workflows.ps1
-DryRun` называет каждый и причину; исправьте его в ComfyUI и сохраните
снова, и следующая проверка его предложит (раздел 6).

**Воркфлоу помечен как `no longer in your folder`.** Вы удалили его из
ComfyUI; LocalCanvas сам определение никогда не удаляет. Сообщение берётся из
записи в `config/local/workflow-inventory.json`, поэтому прекращает его
удаление именно этой записи, а удаление определения в
`config/local/workflows` — нет (измерено). Либо поставьте
`detect_removed: false` в `config/local/workflow-sources.yaml`, чтобы не
получать таких сообщений вовсе.

**`start.ps1` выходит с кодом 6.** Слой воркфлоу не удалось выстроить, и либо
каталога, на котором можно стартовать, нет, либо вы ответили «нет» на
`Start LocalCanvas anyway? [Y/n]` за терминалом, поэтому шлюз не
запускался — что именно случилось, сказано в сообщении выше. Исправьте то,
что там названо, и запустите `pwsh .\scripts\sync-workflows.ps1`.

**Телефон не находит компьютер.** Во многих домашних сетях mDNS не проходит.
Воспользуйтесь QR-кодом или введите адрес — ни то ни другое от mDNS не
зависит. Если и так не достучаться, дело в брандмауэре: проверьте, что порт
шлюза разрешён в брандмауэре Windows для **частных** сетей (раздел 5).

**«Подключено, но ComfyUI не запущен.»** Шлюз ответил, а ComfyUI — нет.
Запустите ComfyUI на компьютере или проверьте `comfy.host` и `comfy.port` в
`config/local/runtime.yaml`.

**Связь оборвалась посреди генерации.** См. раздел 12.

## 14. Командная строка для опытных

Всё, что описано выше, проходит через `LocalCanvas.exe`. Ничего под этим не
изменилось: он вызывает те же скрипты, которые описаны здесь, с флагом
`-Json`, и никак иначе не трогает работающую систему. Пользуйтесь этим путём,
когда Smart App Control блокирует exe (раздел 13), когда у вас компьютер без
рабочего стола, на который можно поместить значок в трее, когда вы управляете
LocalCanvas из чего-то ещё, либо просто потому, что он вам ближе, — это был
весь LocalCanvas до v0.2.0, и он остаётся ровно таким же по возможностям.

**Получить скрипты.** В самом zip-архиве exe уже лежит `scripts\` внутри
распакованной папки — все команды ниже можно выполнять прямо оттуда. Чтобы
работать из клона:

```powershell
git clone https://github.com/shinKatana0/LocalCanvas.git LocalCanvas
cd LocalCanvas
```

Если файлы пришли из скачанного zip-архива, а не из `git clone`, снимите
метку загрузки (Mark of the Web) один раз, прежде чем что-либо запускать,
внутри папки:

```powershell
Get-ChildItem -Recurse | Unblock-File
```

### Установка и запуск

```powershell
pwsh .\scripts\setup.ps1
pwsh .\scripts\start.ps1
```

Эти две команды — весь первый запуск, та же настройка, что описана в
разделе 2, в том же окне PowerShell, только не открытом за вас. Вы не
копируете шаблон, не открываете ни одного YAML-файла, и количество
конфигурационных файлов, которые вы правите руками, равно **нулю**. Setup не
нужен запущенный ComfyUI; `start.ps1` — нужен (или он запускает его сам, если
вы так выбрали).

`setup.ps1` выбирает Python внутри поддерживаемого диапазона и печатает,
какой именно и какой версии. (Если такого нет, он останавливается, ничего не
создав, и говорит установить Python 3.10 – 3.13 либо указать интерпретатор
через `-PythonExe`.) Он собирает `.venv/` в корне репозитория, устанавливает
туда шлюз — всегда как `.venv\Scripts\python.exe -m pip`, поэтому записать
что-либо в Python ComfyUI он не может, — и проверяет, что импортируется
именно *этот* checkout, а не копия, оставшаяся где-то ещё. Затем он задаёт
два своих вопроса (раздел 2), пишет вашу конфигурацию, читает её обратно так
же, как её прочитает `start.ps1`, печатает таблицу состояния и называет
следующую команду.

**Ответить заранее.** У каждого вопроса есть параметр, поэтому запуск без
человека никогда не остаётся ждать: ему говорят, чего не хватает, называют
параметр, который это даёт, и завершают работу.

```powershell
pwsh .\scripts\setup.ps1 -Mode External -ComfyRoot "C:\path\to\ComfyUI"
```

| Параметр | На что отвечает |
|---|---|
| `-Mode External` / `-Mode Managed` | Вопрос 1. Одного `External` достаточно для полного прогона. |
| `-ComfyRoot "C:\path\to\ComfyUI"` | Вопрос 2. |
| `-WorkflowSource "C:\path\to\workflows"` | Вопрос 3, если он был задан. |
| `-ComfyHost`, `-ComfyPort` | Где слушает ComfyUI, если это не `127.0.0.1:8188`. |
| `-PythonExe`, `-VenvPath`, `-Recreate`, `-Dev` | Какой интерпретатор, где окружение, пересобрать его, добавить тестовые зависимости. |

**Повторный запуск setup.** Он идемпотентен: второй прогон на здоровой
установке печатает ту же таблицу состояния и `Nothing to change.` Он ничего
не спрашивает и переустанавливает шлюз только тогда, когда собственная
проверка находит проблему. **Конфигурационный файл, который уже есть, он
оставляет ровно таким, какой он есть.** Если setup не смог выяснить, где
ваши воркфлоу, в таблице состояния будет строка
`Workflow sources   not configured` и команда, которая доводит дело до конца:
`pwsh .\scripts\setup.ps1 -WorkflowSource '<your workflow folder>'`.

**И запустить.**

```powershell
pwsh .\scripts\start.ps1
```

Он загружает конфигурацию, убеждается, что ComfyUI действительно готов
(настоящая HTTP-проверка с опросом, а не фиксированная пауза), проверяет
вашу папку с воркфлоу, запускает шлюз и печатает в терминале ваш адрес и
QR-код. **Не закрывайте это окно**, пока пользуетесь телефоном: если его
закрыть, шлюз тоже остановится — это единственное настоящее отличие от трея,
который продолжает работать после закрытия своего окна и останавливается
только по Exit или при выходе из сеанса.

**В отличие от setup, этой команде ComfyUI нужен запущенным.** Во внешнем
режиме LocalCanvas никогда не запускает его за вас, поэтому не отвечающий
ComfyUI заканчивает запуск строкой `ComfyUI is not reachable` и кодом 4 ещё
до того, как поднимется шлюз. В управляемом режиме он запускает ComfyUI сам и
дожидается его.

При каждом запуске он проверяет вашу папку воркфлоу — та же проверка, что
использует трей:

| Что находит проверка | Что происходит |
|---|---|
| Ничего нового и ничего изменённого | `Workflows: unchanged - nothing new and nothing edited`, и LocalCanvas запускается. Ни синхронизации, ни конвертации, ни вопроса. |
| Что-то новое или изменённое, за терминалом | Сводка в одну строку, например `Workflows: 1 new, 2 changed`, затем `Sync workflows now? [Y/n]`. **Enter означает «да».** |
| Что-то новое или изменённое, спросить некого | Ни вопроса, ни ожидания. Он говорит, что изменилось, называет `pwsh .\scripts\sync-workflows.ps1` и запускается на том каталоге, который уже есть. |

Сеанс, в котором «спросить некого», — это задача планировщика, шаг CI,
конвейер или оболочка с `-NonInteractive`. По замерам — около **4–5,5 секунды
на 250 воркфлоу** (примерно 14–19 мс на каждый), то есть около 8–10 секунд на
500.

```powershell
pwsh .\scripts\start.ps1 -SyncWorkflows      # синхронизировать всё изменённое, без вопроса
pwsh .\scripts\start.ps1 -SkipWorkflowCheck  # вообще не смотреть в папки
```

Они противоречат друг другу: если передать оба, запуск отклоняется и ничего
не стартует.

### Импорт вручную

```powershell
pwsh .\scripts\sync-workflows.ps1 -DryRun
pwsh .\scripts\sync-workflows.ps1
```

**Сначала запустите ComfyUI** — и для `-DryRun` тоже. Пробный прогон ничего
не пишет, но действительно просит ComfyUI конвертировать воркфлоу, сохранённые
через **Save**, чтобы сказать, что импортируется; если никто не отвечает, он
может потратить до четырёх минут, прежде чем сдаться на таком файле.
`-NoConvert` — быстрый отчёт, который у ComfyUI ничего не спрашивает и
помечает каждый такой файл как `NEEDS_API_EXPORT`.

Пробный прогон называет каждый воркфлоу, который он импортировал бы, каждый,
который отложил бы на проверку, и каждый, который не смог конвертировать, с
причиной. Настоящий прогон пишет:

| Что | Куда |
|---|---|
| Определения, которые можно читать и править | `config/local/workflows` |
| Собственные копии графов в формате API | `config/local/imported-workflows` |
| Что найдено в этом прогоне | `config/local/workflow-inventory.json` |

С `-DryRun` `-RegenerateLabels` перечислит ровно то, что заменил бы, и ничего
не запишет; без неё он заменяет каждую сгенерированную подпись новой
(раздел 6).

**Шлюз читает каталог один раз, при запуске.** Синхронизация, выполненная,
пока он уже работает, не будет подхвачена, пока вы не перезапустите его:

```powershell
pwsh .\scripts\stop.ps1
pwsh .\scripts\start.ps1
```

(Трей делает этот перезапуск за вас автоматически, раздел 6.) Прогон импорта,
который упал, и проверка, которая вообще не смогла выполниться, обрабатываются
одинаково: уже имеющиеся определения остаются ровно такими, какими были. За
терминалом он затем спрашивает `Start LocalCanvas anyway? [Y/n]`, по
умолчанию «да»; когда спросить некого, он сообщает и продолжает.
Останавливается он — с кодом выхода **6** и без запуска шлюза, — только когда
откатиться *не на что*, или когда вы ответили «нет».

```powershell
pwsh .\scripts\stop.ps1
pwsh .\scripts\status.ps1
```

Что каждый из них останавливает и о чём сообщает — в разделе 15, независимо
от того, каким путём был запущен LocalCanvas.

### Установка ComfyUI и диагностика машины

`comfy\setup.ps1` и `comfy\doctor.ps1` — те же команды, что при запуске из
трея и из командной строки — целиком в разделе 1, вместе с
`scripts\doctor.ps1` (раздел 13).

## 15. Остановка и внешний ComfyUI

**Из трея:** нажмите правой кнопкой и выберите **Exit** (раздел 4). **Из
командной строки:**

```powershell
pwsh .\scripts\stop.ps1
```

В обоих случаях останавливаются только те процессы, которые запустил сам
LocalCanvas. Если он использовал уже работавший у вас ComfyUI или вы во
внешнем режиме, он оставит его в покое и скажет об этом — именно поэтому
строка ComfyUI в трее говорит `(external)` (раздел 4). Если закрыть окно, в
котором вы запускали `start.ps1`, шлюз тоже остановится; закрытие значка в
трее сам по себе не останавливает ничего — только **Exit**.

**Выход из сеанса Windows или её завершение работы** при работающем трее
останавливает LocalCanvas так же, как Exit, автоматически, и Windows просят
подождать до 45 секунд — она показывает **«Stopping LocalCanvas»** и
удерживает экран выхода вместо того, чтобы завершить лончер после обычных
нескольких секунд. Это по-возможности, а не гарантия: под большой нагрузкой
запуск шлюза, который ещё не закончился, когда этот срок истёк, остаётся
работать, а не прерывается, и об этом сообщается, а не теряется бесследно.

**Одно придётся убрать вам самим в обоих случаях:** чтобы файл попал в
узел-загрузчик, его нужно отдать собственному endpoint'у загрузки ComfyUI, а
ComfyUI его хранит. LocalCanvas складывает их все в одну подпапку
`localcanvas/` во входной директории ComfyUI, чтобы её можно было очистить
одним действием — удалить их сам он не может.

## 16. Известные ограничения

- Сторона компьютера — **только Windows**.
- `LocalCanvas.exe` не подписан. На компьютере с включённым Smart App Control
  он блокируется без вариантов, без диалога «Запустить всё равно»; путь через
  командную строку (раздел 14) этим не затронут, и именно им сопровождающий
  пользуется каждый день.
- Сам трей-лончер не проверялся целиком на компьютере с выключенным Smart App
  Control — см. «Что проверялось» в разделе 1.
- Вручную сопровождающий проверил подключение и генерацию на одном складном
  телефоне по Wi-Fi с настоящим ComfyUI. Автоматически этот путь не покрыт
  ничем.
- Отправка картинки или видео с телефона пока не подтверждена как работающая.
- Перевод промпта и обнаружение по mDNS на телефоне проверялись только на
  имитациях.
- Воркфлоу, отложенному как `NEEDS_REVIEW`, нужен человек, который решит, что
  в нём показывать.
